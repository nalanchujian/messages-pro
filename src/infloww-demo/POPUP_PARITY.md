`crm-pc-client-web/src/pages/onlyfans/of-manager/message.tsx` embeds `/my/chats/` through `OfManager`. Native OnlyFans dialogs are therefore not defined in that web page. The sibling desktop client contains its injection components. The newer `message-pro2` project is a separate message implementation; its shared list behavior is identified separately below.

## Priority interaction pass — 2026-10-15

- Fan signals now retain every matching signal, ordered expired, new, renewal off, recent PPV, snow. The highest-priority signal determines the avatar; hovering the avatar or focusing the conversation shows descriptions for the complete set. **Correction to the earlier audit:** `handleChatList.tsx` lines 123–156 also require positive spend for snow and use the latest chat timestamp. That condition is retained; the official guide's shorter wording is not used to replace the supplied implementation.
- A notification's chat action opens and selects a dedicated fan tab. Reopening reuses that tab. The Home conversation, its draft and the target fan's draft are retained. Notification quick replies still send without changing the active conversation.
- The timer entry offers Timed message and Timed reminder, following the official Messages Pro guide. Timed messages take a separate draft snapshot, duration, media, price and creator tags; Cancel discards the editor and Start queues that snapshot without changing the main draft. Both modes can be cancelled. Due messages execute once after restoration; blocked or failed delivery does not report successful sending. The supplied older client exposes only the reminder dialog, so the exact geometry of the newer two-mode menu and timed-message editor remains unverified.
- The Notes card gear opens a staged Fan note template editor. Cancel discards edits, Save persists a creator-specific template, and new fans or fans with empty notes use it. Existing fan notes and Creator notes are preserved. Templates are editable by both demo roles, as documented in the official Fan Insights guide. The guide confirms this behavior, but the exact production editor geometry is not available in the supplied screenshots/source.

## Online audience and withdrawal pass — 2026-10-15

- Online fans supports spend/tip thresholds, subscription status/duration, excluded lists, excluded creators and recent-contact hours. The list chooser is an anchored searchable multi-select with removable chips. Filters persist per creator, are carried into Message all, and determine the actual eligible recipient set. Zero matches disable Send; dispatch rechecks eligibility for scheduled delivery. Evidence: `crm-pc-client/src/preload/components/onlineMsg/utils.ts` (`FansFilter`) and the official OnlyFans Messages Pro guide's Online Fans section. Exact production filter geometry is unavailable. A subscription month is approximated as 30 days in this demo.
- Withdrawing an eligible message creates an agency-level record containing the original message, media, price, sender and withdrawing user. Admins see a transient alert and an unread badge on the global bell. The history page supports delayed hover preview, View details, nested media preview, a confirmed Mark all as read action and Go to chat. Chatters cannot access or mark agency records read. Evidence: `crm-pc-client-web/src/pages/settings/notification/notification-components/NotificationItem.tsx`, `MessageInfo.tsx`, `Notification.tsx`, and the official guide's Message Withdrawal Alerts section. This is a local demo ledger, without backend or cross-user notification delivery.
- The withdrawal detail follows the supplied non-mask-dismissible modal, metadata and first-three-media preview behavior. Go to chat uses the existing dedicated fan tab; the source's separate lightweight window is not reproduced. New outbound messages expose withdrawal immediately without waiting for the periodic UI clock tick. Failed/purchased messages and expired withdrawal windows cannot create records. Delivered campaign cancellation cannot bypass the record.
- Browser verification covered inherited exclusions, one matching recipient in the actual send report, zero-match Send disabling, media snapshots, nested preview, creator/fan navigation and records surviving a new page load. It also confirmed the chatter view hides the agency entry/alert, the admin view retains the unread record, cancelling Mark all leaves it unread, and confirming clears it. State tests cover scheduled rechecking, role guards, idempotent withdrawal, retained snapshots after chat clearing and backward-compatible restoration. A narrow-rail spending amount no longer breaks across lines; its type scales with the card width.

## Main-interface and popup completion — 2026-10-15

- Scope: primary Messages Pro interface and modeled popups use local mock state. Page destinations (More Scripts, full statistics, profiles, new windows, brand/original workspace and agency notification center) show a Toast and keep the workspace. Internal creator/fan tabs, result overlays and withdrawal-alert details still work in place. The previously implemented agency-history component remains local code, but the bell no longer navigates into it.
- Scripts: one-second dark hover detail, content/note/founder, media carousel, individual indexed preview and sent-by hints. Media badges respect attachment-level free previews. Preview sends carry script attribution and release-form IDs; main draft remains independent. Evidence: desktop `ScriptList/ScriptsPopover/index.tsx`, `ScriptsItem/index.tsx`, `ScriptList/index.tsx`. Full management is outside scope.
- Vault: status badges open a local send/purchase/withdrawal timeline; info shows notes/tags and supports staged edit. Thumbnail preview and checkbox selection remain separate; Add commits, Close discards. Outbound successful messages count as sent; replies/failed/sending do not. Free-preview media do not inherit the parent's paid price. Withdrawal snapshots retain history after chat clearing. Evidence: bundled design library `Vault/components/MediaItemBox/MediaItemBox.js`, `MediaHistoryList.js`.
- Sales: per-asset viewer opens at the clicked index; hover summarizes media types and message text. Six assets are visible before Read more/Collapse. The grid uses native 75 px tiles where space permits, shrinking to keep three columns on narrower rails. Copy as draft never sends. Timeline thumbnails, details and drag scrolling follow `fansInfoPro/Ppv/PpvItem/index.tsx` and the related chart source.
- Profiles: explicit mock organization/risk states, expired/expiring dates, independent pay-date storage and two-decimal salary truncation. Creator notes are editable by both demo roles, consistent with the inspected note editor; default nickname retains the demo's admin rule. Pinned lists use the separate newer shared implementation's immediate checkboxes, My lists/New list/Refresh and nested creation.
- Shared popovers now defer to nested modal dialogs on Escape/outside interaction. Shared media viewers support arrow keys from the initial focus, indexed navigation and top-dialog-only closing. Campaign validation and release-form qualification are also checked by the reducer, not only the UI.

Native OF overlays listed above still require direct reference captures before claiming exact visual parity. Full external pages, production account services and independent native windows are outside this mock-only scope. `INTERACTION_COVERAGE.md` inventories the modeled primary controls and popup outcomes; it does not claim exhaustive current-production feature discovery.

The test suite verifies state transitions and draft isolation. Browser checks verify popup placement, nested media preview, staged media selection, dismiss behavior (including Escape closing only the top dialog), countdown validation, favorite reordering, list updates, calendar selection and region search. Neither passing tests nor matching the outer screenshot proves full production UI parity.
